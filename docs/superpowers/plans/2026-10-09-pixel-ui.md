# Pixel UI Overhaul Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the generic "dark neon dashboard" UI with a pixel-art UI that matches the game's sprites and industrial tileset: one pixel font, one palette, one set of bevelled pixel primitives, and hand-made pixel icons instead of emoji, on every screen and on the canvas.

**Architecture:** A global design system (`src/styles/tokens.css` + `src/styles/ui-kit.css`) holds the palette, type scale and shared primitives (`.px-panel`, `.px-btn`, `.px-bar`, ...). Pixel icons are character grids in `src/app/ui/pixel-icons.ts`, rasterised once to a cached 1x canvas (`pixel-icon-raster.ts`) that both the DOM (`<app-pixel-icon>`) and the canvas engine (`drawImage`, smoothing off) draw from. Every `icon: string` (emoji) field in `shared/` becomes `icon: PixelIconId`. Then each screen is restyled onto the kit.

**Tech Stack:** Angular 21 standalone components + signals, plain component CSS (Tailwind 4 is imported but unused by templates), Canvas 2D engine, Vitest, Playwright e2e. New dependency: `@fontsource/pixelify-sans` (self-hosted, no network at runtime).

**Spec:** the UI audit in this session: no web font, ~76 emoji icons, 35 coloured glow shadows, 8 border radii, ~30 font sizes, 6 button styles, unused `:root` variables, smooth UI over pixel art.

## Global Constraints

- Font: `'Pixelify Sans'` (weights 400, 500, 700) everywhere, DOM and canvas. No Impact, Segoe UI or `monospace` in UI CSS.
- Type scale (px only, no rem): 12, 14, 16, 20, 28, 40, 64. Nothing smaller than 12px.
- Corners: `border-radius: 0` on every UI element (pixel look). Only exception: none.
- Shadows: hard offset shadows only (`Npx Npx 0`). No blurred `box-shadow`, no `text-shadow` blur, no `backdrop-filter`. Canvas `shadowBlur` only for crit damage numbers and level-up.
- Colours only through `var(--…)` tokens from `src/styles/tokens.css`. No new hard-coded hex in component CSS.
- No emoji anywhere in the UI or canvas text. Icons are `<app-pixel-icon>` / `drawPixelIcon`. Keyboard arrow glyphs on key caps (← ↑ → ↓, Pg↑) stay as text.
- Copy: sentence case, letter-spacing ≤ 0.05em. Only the game logo and the "Game over" title may be upper case.
- Repo hard rules (CLAUDE.md): explicit types on everything, no unused code, `templateUrl` + `styleUrl`, shared types in `shared/`, no new `console.*`, Prettier only on new files. `data-testid` attributes must survive untouched (e2e depends on them).
- `shared/` changes ⇒ frontend build **and** `zombie-blaster-api` build must pass.

## Review Focus

1. **Font not loaded yet when the canvas first draws** → canvas text falls back to serif for a frame. Expected: canvas uses the pixel font from the first game frame. Test: e2e guard spec asserts `document.fonts.check('16px "Pixelify Sans"')` is true on the game page (Task 8).
2. **An emoji left behind** in some rarely opened panel (dev dialog, special-drop dialog, tooltip). Expected: zero emoji in visible text. Test: e2e guard spec scans `document.body.innerText` for `\p{Extended_Pictographic}` on menu, character select, lobby, game HUD, shop, inventory, stats, skills, settings (Task 8).
3. **Icon id with no grid** (typo in game-constants) → blank image or crash in rasteriser. Expected: compile error. Test: `PIXEL_ICONS` typed `Record<PixelIconId, PixelIconDef>` + unit test that every grid is rectangular and every char is in its palette (Task 2).
4. **Small screens** (1280×720 and 1024×640) → HUD bars/action bar overlap or modals overflow. Expected: everything fits, modals scroll internally. Test: Task 8 screenshots at 1280×720; modals keep `max-height` + `overflow:auto`.
5. **Upper-case text asserted by e2e** (`navigation.spec.ts` expects `['NEW GAME', ...]` via `innerText`, which applies `text-transform`). Expected: spec updated to the new sentence-case labels in the same change (Task 4).

  text: string,
  x: number,
  y: number,
  fill: string,
  outline: string = '#0e0d0b',
  outlineWidth: number = 3,
): void {
  ctx.lineJoin = 'miter';
  ctx.miterLimit = 2;
  ctx.lineWidth = outlineWidth;
  ctx.strokeStyle = outline;
  ctx.strokeText(text, x, y);
  ctx.fillStyle = fill;
  ctx.fillText(text, x, y);
}
